## 哪些代码写得好

1. CNN 的尺寸推导正确：28→14→7，Linear 输入 32×7×7；返回 logits，训练没有多余 Softmax。
2. zero_grad → forward → loss → backward → step 的顺序正确，训练与验证用了正确模式。
3. loss 乘以 batch 大小后累加，再除总样本数，避免最后一批较小时的统计偏差。
4. 训练与验证用同一组索引划分、不同 transform，避免把随机增强带进验证。
5. 以 val_loss 做早停，使用 deepcopy 保存最佳 state_dict，这些写法应保留。
6. 推理使用 eval、no_grad、map_location 和 weights_only；已有设备切换、Softmax、Top-3 思路正确。
7. 手动计算 Conv/ReLU/Pool 中间值，而非全部封装起来，有助于解释 CNN。

训练和验证的两段循环，以及几个脚本中的权重加载存在少量重复。对于当前学习项目，保留展开形式更容易读；去掉了真正不使用的全局 loader，没有引入通用 Trainer 或工具层。
